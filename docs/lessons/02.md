# 02 · The withdraw circuit

The circuit proves, in zero knowledge:

1. I know `(nullifier, secret)` whose commitment sits in a Merkle tree with
   public `root`.
2. `nullifierHash = Poseidon₂(nullifier, 1)`.
3. The public `recipient` and `fee` are bound (they are public inputs, so a
   prover cannot swap them after proving without a new proof).

Public input **order** (load-bearing, see lesson 04):

```
root, nullifierHash, recipient, fee
```

Private: `nullifier, secret, pathElements[8], pathIndices[8]`.

`pathIndices[i] === 0` means the current node is the **left** child:
`hash2(current, sibling)`. `1` means right: `hash2(sibling, current)`.

Use `poseidon_classic::hash2` in Noir and `Hash2()` in Circom — they match
`packages/shared` and CAP-0075.

## Hints

<a id="hints"></a>

**Hint 1 — concept.** You are proving Merkle membership of a commitment you
derived from a hidden note, plus a tagged nullifier hash, plus binding the
payout parameters.

**Hint 2 — shape.**

```
c = hash2(nullifier, secret)
cur = c
for i in 0..8:
    cur = path_indices[i] == 0 ? hash2(cur, path[i]) : hash2(path[i], cur)
assert cur == root
assert nullifierHash == hash2(nullifier, 1)
assert recipient * recipient >= 0   # keep the public value constrained
assert fee * fee >= 0
```

Vector 1: nullifier=1, secret=2, two-leaf tree in `golden.json`.

**Hint 3 — near-code.** In Noir, `path_indices[i]` is a `Field`. Compare with
`0` and use `if` (Noir 1.0 allows this on Fields in this constrained context
if you convert: `if path_indices[i] as u32 == 0`). In Circom, use a mux:
`HashLeftRight` with `pathIndices[i]` selecting the order, or two hashes and
`s * (a-b) + b`. Do not copy tornado_classic.
