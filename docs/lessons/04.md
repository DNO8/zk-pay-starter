# 04 · Public inputs, encodings, recipient/fee binding

The circuit and the contract must agree on **order**, **endianness**, and
**which values are public**.

## Order

```
0. root            U256 / Field     Merkle root used in the proof
1. nullifierHash   U256 / Field
2. recipient       Field            see below
3. fee             Field / i128
```

Defined in `packages/shared/src/encode.ts` as `WITHDRAW_PUBLIC_ORDER`.

## Encodings

- **UltraHonk:** `N × 32-byte big-endian` fields. bb.js already emits this.
  The on-chain verifier takes `public_inputs: Bytes` and `proof_bytes: Bytes`.
- **Groth16:** `4-byte big-endian length || N × 32-byte big-endian` fields.
  Proof is `G1(A) || G2(B) || G1(C)` with CAP-0074 uncompressed points
  (`G2 = X_c1|X_c0|Y_c1|Y_c0`). Helpers: `encodeGroth16Proof`,
  `encodeG16PublicSignals`.

## Recipient as a field

A Stellar `Address` is 32 bytes and may be ≥ the BN254 modulus. Convert with
the same rule in TypeScript and in the contract:

```
recipient_field = U256::from_be_bytes(address_bytes)  mod r
```

(`r` is in `poseidon.params.json` as `field_modulus`.) The circuit takes that
field as a public input, so a relayer cannot redirect the payout without a
new proof. Same for `fee`.

## GAP-5

`Pool::withdraw` must: check the root is known, pack public inputs in this
order, call the verifier, then pay `denomination - fee` to `recipient` and
`fee` to `relayer`. Named test: `withdraw_verifies_vector_proof`.

## Hints

<a id="hints"></a>

**Hint 1 — concept.** If recipient is not a public input, the proof is valid
for any destination. That is a theft bug, not a feature.

**Hint 2 — shape.** For UltraHonk, concatenate four 32-byte BE fields and pass
them as `public_inputs`. For Groth16, use `encodeG16PublicSignals` / the same
layout as `verifier-groth16`. Call `verify_proof` / `verify`. On success,
`token.transfer(pool, recipient, denom - fee)`.

**Hint 3 — near-code.** `HELLO_UH` shows the invoke pattern in
`scripts/verify.ts`. Reuse `poseidon_hash2` only for the tree; the verifier
does not re-hash the note. Reject a tampered proof by checking the verifier's
error, not by panicking later.
