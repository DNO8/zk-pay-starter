# 03 · On-chain Merkle insert and root history

Deposits append a commitment as the next leaf of a Poseidon Merkle tree of
depth 8. The contract stores the **current root** and a **ring buffer of the
last 32 roots**. Withdrawals may use any root still in that history, so a
deposit that lands while you are proving does not invalidate your proof.

Empty leaves are `0`. The zero-hashes `z[i] = hash2(z[i-1], z[i-1])` with
`z[0] = 0` are in `golden.json`.

The pool already exposes `hash2` (CAP-0075, same params). Use it. Do not
reimplement Poseidon in WASM.

## GAP-3

## Hints

<a id="hints"></a>

**Hint 1 — concept.** Each deposit fills the next index. Recompute only the
nodes on the path from that leaf to the root. Keep old roots so in-flight
proofs still verify.

**Hint 2 — shape.**

```
index = NEXT
store Node(0, index) = commitment
cur, i = commitment, index
for level in 0..DEPTH:
    sibling = Node(level, i^1) or zeros_at(level)
    cur = (i % 2 == 0) ? hash2(cur, sibling) : hash2(sibling, cur)
    i >>= 1
    store Node(level+1, i) = cur
ROOT = cur
RootHist[NEXT % 32] = cur
NEXT += 1
```

After one deposit of `hash2(1,2)`, `current_root()` equals
`golden.merkle.root_after_1`.

The `deposit` function currently transfers the token and returns `index`
